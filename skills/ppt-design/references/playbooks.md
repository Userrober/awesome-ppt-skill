# Scenario playbooks: skeletons you can trust

Each playbook fixes: slide budget, skeleton, title style, and the ask. Adapt
content, not structure.

## Weekly report / 周报（5–8 slides, 10 min）

1. **结论页** — assertion title with the 2–3 headline facts (answer-first)
2. 亮点 ×1 — the win, with the number that proves it
3. 风险 ×1 — each risk paired with the decision/help you need
4. 数据页 — the one metric table/chart the team tracks
5. 下周计划 — owners + dates, max 5 rows

Ask: "需要各位拍板的" listed explicitly on the risk slide.

## Tech talk / 技术分享（10–15 slides, 30 min, journey skeleton）

1. Hook: the failure/incident/scale that motivated the work (real numbers)
2. Why it's hard — the three constraints that fight each other
3. Key idea — ONE slide, one diagram, this is the talk's spine
4. How it works — 3–4 slides, each ending in a takeaway sentence
5. Results — before/after chart; the axes matter more than the bars
6. What I'd do differently — earns the audience's trust
7. Links/repo — one slide, small

## Pitch / 路演（10–12 slides, 5–8 min, SCQA compressed）

Market (why now) → problem (who bleeds) → solution (one slide, one diagram) →
why us (the unfair advantage) → traction (chart, honest scale) → business model
(one line) → ask (金额 + 用途 + 里程碑). Never let the demo slide be a
screenshot wall; one screenshot, annotated.

## Project review / 项目评审（8–12 slides, pyramid skeleton）

1. 结论与请求 — what is being decided today
2. 背景一段 — only what a new reviewer needs
3. 方案 — the chosen design + the two alternatives considered and why rejected
4. 数据/实验 — the evidence with error bars / caveats stated
5. 风险与回滚 — what breaks, detection, plan B
6. 里程碑 — owner + date table

Reviewers object to unstated trade-offs; state them before they find them.

## Course lecture / 课程（per 45 min: 12–18 slides）

Concept → intuition (analogy) → formal definition → worked example →
trap/misconception → exercise. Every 5 slides, one "checkpoint" slide asking
the audience a question. 排版字号按教室后半排能读：正文 ≥ 20pt。

## Cross-scenario rules

- The **ask slide** always: decision needed / owner / date. A deck without an
  ask is a document.
- Numbers need units, time ranges, and a source line (10pt, bottom).
- Anything the audience might audit goes to backup slides, not the bin.
